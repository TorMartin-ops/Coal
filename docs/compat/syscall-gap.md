# Syscall gap: what real workloads need that Coal does not implement

Generated by `tools/harness/syscall_gap.py`. Each workload ran on x86_64 Linux under `strace -f`; the
syscalls it used are compared by name with Coal's table (`kernel/cpu/syscall.c`, i386). Pure ABI renames
are folded first (`mmap2` is `mmap`, `stat64` is `stat`, `getuid32` is `getuid`, `set_thread_area` stands
in for `arch_prctl`). Workloads start through `sh -c`, as an agent runs them, so the shell's own calls count too.
To regenerate: `tools/harness/syscall_gap.py --collect /tmp/gap-logs --markdown docs/compat/syscall-gap.md`.

Coal implements 95 syscalls by this count. A name in the table can still fail for some arguments; see the last section.

## In the table but incomplete

These return `-ENOSYS` for some arguments, so a workload using them can still fail:

- `mmap`: `if (!(flags & MAP_ANONYMOUS) || fd != -1) return -ENOSYS;   /* file mappings are not supported */`
- `newfstatat`: `if (dirfd != AT_FDCWD) return -ENOSYS;`
- `openat`: `if (dirfd != AT_FDCWD) return -ENOSYS;          /* directory-relative lookup is not supported */`
